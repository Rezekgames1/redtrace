# Архитектура RED//TRACE

## Границы первой версии

Приложение анализирует только локальный компьютер. Сетевой сервер, облачная синхронизация и удалённое управление по умолчанию отсутствуют.

```text
platform collectors -> parsers -> normalized events -> segment writer
                                                  -> indexes
indexes + query AST -> query executor -> local API -> web UI / CLI
```

## Компоненты

Архитектура разделена на два независимых контура: нативное ядро на Rust отвечает за сбор, нормализацию, индекс и поиск; UI отвечает только за представление и состояние рабочего места аналитика. Интерфейс можно заменить без миграции данных или изменения языка запросов.

### `model`

Нормализованное событие содержит обязательные timestamp, source, level и message, а также динамические поля. Имена вроде `event.id`, `process.name`, `user.name` сохраняют одинаковый смысл на разных ОС.

### `query`

Рукописный лексер и recursive-descent parser не требуют генератора грамматики. Текущий приоритет операторов: `NOT`, затем `AND`, затем `OR`.

### `index`

Первая вертикаль использует:

- `field -> value -> document IDs` для точных фильтров;
- `term -> document IDs` для текста;
- операции над упорядоченными множествами для булевых выражений.

Следующий этап заменит множества на сжатые postings/bitmaps и добавит неизменяемые дисковые сегменты. API и AST при этом не меняются.

### `audit::windows`

Модуль описывает действия как данные: цель, ожидаемые Event ID, точная команда и стратегия отката. API пока возвращает только preview. Выполнение будет доступно исключительно в Windows-сборке.

### `app/events`

Фронтенд использует узкую границу данных: `types.ts` описывает нормализованное событие, а `api.ts` инкапсулирует localhost API и преобразование ответа. Экран не знает формат транспортного JSON и может позже перейти с HTTP на Tauri IPC без переделки панелей.

Рабочее место строится вокруг одного состояния выбранного события и четырёх независимых представлений:

```text
запрос + диапазон времени
          |
          v
поля -> поток событий -> подробности
             |
             v
       гистограмма времени
```

На широком экране поля, поток и подробности видны одновременно. На компактном экране поток остаётся основным контекстом, а поля и подробности открываются как боковые панели с затемнением фона. Это сохраняет одну информационную архитектуру на Windows, Linux и macOS.

## Визуальная система

- шаг компоновки 4/8 px, высота основных контролов 34 px;
- нейтральные почти чёрные поверхности и один бирюзовый акцент для выбора и живого состояния;
- красный и янтарный зарезервированы для риска, а не для декора;
- моноширинный шрифт используется только для времени, идентификаторов, запросов и сырых данных;
- плотность рассчитана на длительную работу: строка события 58–62 px, подробности раскрываются отдельно;
- адаптивный порог 820 px переводит вспомогательные панели в drawers без потери функций.

## План сегментного хранилища

```text
data/
  catalog.json
  active.wal
  segments/
    00000001/
      meta.bin
      events.zst
      fields.dict
      fields.postings
      terms.dict
      terms.postings
      timestamps.bin
```

Закрытые сегменты неизменяемы. По времени в метаданных хранится min/max, поэтому нерелевантные сегменты пропускаются до чтения. Удаление по retention удаляет целые сегменты.

## Целевые бюджеты

- idle RSS до 50 МБ;
- активный сбор до 100 МБ;
- отсутствие фонового полного сканирования;
- жёсткий лимит диска и retention;
- запуск UI и API менее чем за две секунды в release-сборке.

## Текущий этап

Сейчас готов вертикальный прототип: собственный DSL и индекс в памяти, localhost API, read-only сбор macOS Unified Log и полноценное рабочее место поиска. Рабочий контур не подставляет демонстрационные события. UI поддерживает адаптивные панели, изменение их ширины и обязательный процессный контекст (`event.description`, `process.command_line`, `process.pid`, `process.parent.pid`).

До MVP остаются четыре инженерных блока:

1. Расширить нативные read-only коллекторы: Endpoint Security на macOS, journald/auditd на Linux, Event Log/Sysmon на Windows.
2. Дисковое сегментное хранилище с WAL, retention и контролируемым лимитом размера.
3. Добавить непрерывное обновление и инкрементальную агрегацию вместо периодического полного чтения окна Unified Log.
4. Подписание сборок, установщики и безопасный мастер аудита с preview/rollback.
