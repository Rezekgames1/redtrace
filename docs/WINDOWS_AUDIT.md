# Профиль Windows Audit

## Рекомендуемый профиль рабочей станции

| Возможность | События | Настройка |
|---|---:|---|
| Успешный и неуспешный вход | 4624, 4625 | Audit Logon success + failure |
| Блокировка учётной записи | 4740 | Audit User Account Management success |
| Создание процесса | 4688 | Audit Process Creation success |
| Командная строка процесса | 4688 | `ProcessCreationIncludeCmdLine_Enabled=1` |
| PowerShell script blocks | 4104 | `EnableScriptBlockLogging=1` |
| Sysmon | 1, 3, 7, 11, 12, 13, 22 | локальный проверенный бинарник + XML-профиль |

`auditpol` вызывается с GUID подкатегорий, а не локализованными именами. Это позволяет использовать один профиль на русской, английской и других локализациях Windows.

## Последовательность применения

1. Проверить Windows-версию и права пользователя.
2. Снять текущую конфигурацию `auditpol /backup`.
3. Экспортировать только изменяемые ветки реестра.
4. Показать пользователю команды и предупреждение о чувствительных данных.
5. Получить явное подтверждение.
6. Применить выбранные пункты с повышением прав через UAC.
7. Повторно прочитать политики и подтвердить результат.
8. Начать чтение новых каналов событий.

При ошибке шаги откатываются в обратном порядке.

Транзакционное ядро и отдельный Windows dev-helper реализованы. Применение доступно только через Tauri IPC при `REDTRACE_AUDIT_DEV=1`; HTTP API остаётся preview. Helper принимает только четыре встроенных action IDs, требует точную строку подтверждения, использует UAC, named pipe с взаимной проверкой PID/пути и межпроцессную блокировку. Snapshot policy/registry хранится под administrator/SYSTEM-only ACL. Apply проверяется повторным чтением effective state; rollback восстанавливает только выбранные настройки и проверяет результат. Полный `auditpol /backup` сохраняется для диагностики, но не используется для широкого автоматического restore.

На хосте подтверждён apply/verify/rollback всех четырёх настроек; исходные registry values и audit flags восстановлены. Неподписанная dev-сборка разрешена владельцем. Production-подпись остаётся отдельным gate.

Если ответ потерян после применения, UI позволяет восстановить последний защищённый snapshot с отдельным подтверждением `ROLLBACK REDTRACE AUDIT`. Операция, которая превысила timeout, считается неопределённой, а не отменённой: новая операция не запускается, пока elevated helper ещё работает.

## Sysmon

RED//TRACE не должен скрытно скачивать или устанавливать драйвер. Пользователь выбирает локальный `Sysmon64.exe` либо явно разрешает скачивание с Microsoft. Перед запуском проверяются Authenticode-подпись, издатель и хэш файла. XML отображается пользователю и проверяется командой Sysmon до установки.

Базовый профиль находится в `assets/windows/sysmon-redtrace.xml`. Он сознательно не включает наиболее шумные классы событий без фильтров.

Реализован отдельный путь мастера для официального Sysmon 15.22 с проверкой WinVerifyTrust и утверждённым SHA-256. Payload кэшируется после preview и передаётся elevated helper через authenticated IPC; executable/config создаются в protected directory. Перед установкой проверяется отсутствие стандартных служб Sysmon. Snapshot сохраняет stage, config dump hash и service-key identity; удаление не применяется к изменившейся или сторонней установке.

На этом хосте Sysmon 15.22 установлен и оставлен по явному указанию владельца; служба и boot-start драйвер работают. Профиль принимает схему 4.82. Живое событие ProcessCreate с PID/PPID/command line получено через native subscription.

## Read-only права

Отдельная операция GRANT REDTRACE LOG READ получает SID пользователя из token проверенного desktop-процесса. Caller не передаёт SID или произвольный channel. Допускаются только Security и Sysmon, добавляется ACE с mask 0x1; write/clear не выдаются. Исходные O/G/D/S сохраняются в protected snapshot. Restore проверяет scope и intervening changes; повторный no-op grant не заменяет исходный rollback reference.

На хосте проверены grant, normal-user чтение обоих каналов, restore исходных ограничений и повторный grant. Итоговое состояние по разрешению владельца: текущему пользователю оставлен read-доступ. Непривилегированный UI/core не повышается целиком.

## Приватность

Аргументы процессов и содержимое PowerShell могут включать пароли, токены, строки подключения и персональные данные. UI обязан показывать это предупреждение, а экспорт и локальная база должны наследовать строгие разрешения текущего пользователя.
