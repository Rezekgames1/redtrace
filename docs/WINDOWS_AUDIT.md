# Профиль Windows Audit

## Рекомендуемый профиль рабочей станции

| Возможность | События | Настройка |
|---|---:|---|
| Успешный и неуспешный вход | 4624, 4625 | Audit Logon success + failure |
| Блокировка учётной записи | 4740 | Audit Account Lockout failure |
| Создание процесса | 4688 | Audit Process Creation success |
| Командная строка процесса | 4688 | `ProcessCreationIncludeCmdLine_Enabled=1` |
| PowerShell script blocks | 4104 | `EnableScriptBlockLogging=1` |
| Sysmon | 1, 3, 7, 11, 12, 13, 22 | локальный проверенный бинарник + XML-профиль |

`auditpol` вызывается с GUID подкатегорий, а не локализованными именами. Это позволяет использовать один профиль на русской, английской и других локализациях Windows.

## Последовательность применения

1. Проверить Windows-версию и права пользователя.
2. Снять текущую конфигурацию `auditpol /backup`.
3. Экспортировать только изменяемые ветки реестра.
4. Показать пользователю команды и предупреждение о чувствительных данных.
5. Получить явное подтверждение.
6. Применить выбранные пункты с повышением прав через UAC.
7. Повторно прочитать политики и подтвердить результат.
8. Начать чтение новых каналов событий.

При ошибке шаги откатываются в обратном порядке.

## Sysmon

RED//TRACE не должен скрытно скачивать или устанавливать драйвер. Пользователь выбирает локальный `Sysmon64.exe` либо явно разрешает скачивание с Microsoft. Перед запуском проверяются Authenticode-подпись, издатель и хэш файла. XML отображается пользователю и проверяется командой Sysmon до установки.

Базовый профиль находится в `assets/windows/sysmon-redtrace.xml`. Он сознательно не включает наиболее шумные классы событий без фильтров.

## Приватность

Аргументы процессов и содержимое PowerShell могут включать пароли, токены, строки подключения и персональные данные. UI обязан показывать это предупреждение, а экспорт и локальная база должны наследовать строгие разрешения текущего пользователя.
