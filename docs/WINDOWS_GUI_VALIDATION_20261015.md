Первый прогон имел две ошибки сценария: description проверялся на вкладке Summary вместо «Все поля», а Cases предполагал отсутствующий Delete. Сценарий исправлен, затем весь прогон повторён. Исходные результаты сохранены отдельно; исправлений продуктового кода этот этап не потребовал.

## Визуальное ревью

Отдельная OpenCode-сессия просмотрела все 16 реальных PNG первого прогона. Крупных наложений, error/loading страниц и переполнения основного документа не обнаружено. Остались замечания:

- В Diagnostics при ширине 1024 подпись `last_event_at` сокращается до `last_...`.
- Длинные значения exclusion DSL и macOS event list обрезаются внутри узких полей Settings, включая ширину 1440.
- Вторичные подписи и заголовки таблиц мелкие и бледные; контраст инструментально не измерялся.
- Внизу боковой навигации виден горизонтальный scrollbar.

Статическое ревью не подтверждает функциональные действия; они проверены отдельным итоговым прогоном выше.

## Восстановление установленной версии

Проверены неизменный SHA-256 установленного GUI, исходные пути данных/TLS, рабочий каталог, владелец процесса, собственный core и оба исходных listener. UI Automation подтвердила LIVE и 100 отображаемых событий. Тестовые процессы и debug listener отсутствуют.

Готовность установленного core после восстановления заняла около шести минут и превысила первоначальный timeout сценария. В это время процесс расходовал CPU; наблюдалось около 2,36 GB working set. Первоначальный timeout сохранён, успешное восстановление подтверждено последующими read-only проверками без дополнительного перезапуска. Причина задержки не установлена; установленный core отличается от проверенного release core. В установленном GUI также отображаются недоступные каналы: состояние всех каналов этим этапом не подтверждено.
