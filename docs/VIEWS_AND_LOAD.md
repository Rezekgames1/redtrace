# Представления, колонки и короткая нагрузочная проверка — 08.10.2026

## Реализовано

В журнале событий доступны «Представления» и «Колонки».

- Представление хранит последний **выполненный** запрос, режим contains/DSL и упорядоченный набор колонок. Неисполненный черновик не сохраняется вместо активного поиска.
- Поддерживаются создание, открытие, обновление/переименование и удаление. Максимум 32 представления, имя 1–64 символа, запрос до 4096 символов.
- Настройки сохраняются локально в `redtrace.event-preferences.v1` и доступны между загрузками интерфейса. События, API/agent tokens и настройки системного аудита туда не записываются.
- Колонки можно добавлять, убирать и двигать влево/вправо. Доступны стандартные поля и поля текущих событий; максимум 8 колонок, `event.description` остаётся обязательным.
- «Стандартные колонки» возвращает исходный набор. Для широкого пользовательского набора предусмотрена согласованная горизонтальная прокрутка заголовка и строк.
- Некорректный/слишком большой JSON, неизвестная версия, дубли колонок/IDs и недопустимые названия полей нормализуются без падения GUI. Ошибки localStorage отображаются пользователю, не выдаются за успешное сохранение.

Сохранённые запросы могут содержать введённые пользователем значения: передача настроек другому человеку должна учитывать их содержимое. Автоматического экспорта/синхронизации представлений наружу нет.

## Проверки GUI

```powershell
node scripts/smoke-desktop-ui.mjs --preferences --live-ui --filters
```

В настоящем Windows WebView прошли: добавление PID, удаление пользователя, перестановка колонок, обязательность описания, сохранение выполненного поиска при изменённом черновике, восстановление колонок после reload, открытие и rename/delete представления. Тест сохраняет и восстанавливает исходные local preferences; неизвестные пользовательские представления не удаляются.

Также прошли native Sysmon→SSE→UI (замер 1372 ms), pause/resume/pinned details, network recovery, скрытые event-search в Sources отсутствуют, возврат в Events догоняет новый event. 9 Node UI/render/validation tests, ESLint, TypeScript и desktop builds прошли.

Linux GTK/WebKit из пересобранного `.deb`: 594 indexed events, 100 API/UI rows, новый journald event появился за 997 ms. Авторизация, single instance, window-close/sidecar cleanup прошли. CRUD-проверка представлений через реальные controls выполнена на Windows; Linux использует тот же frontend и storage validation, отдельный Linux CRUD walkthrough не выполнялся.

## Короткий burst

```powershell
node scripts/smoke-desktop-ui.mjs --soak-seconds 60
```

Сценарий использует только временную базу desktop и отдельного локального validation agent. Нагрузка — явно обозначенные синтетические fixtures, а не подставленные в рабочую базу demo events. Native collector остаётся активен. Перед запуском проверяются свободные порты 9710/9711/9225; неизвестные процессы не завершаются.

Две burst-фазы по 2000 fixtures плюс steady target 25 events/s, сегменты по 1 MiB. Отчёт: `outputs/soak-short/report.json`.

## Незавершённый длинный запуск

30-minute runner завершился с `FAIL` через 941 секунду: 22675 fixtures отправлено, 5 retry, последняя проверка GUI catch-up не прошла. Его исходный отчёт сохранён в `outputs/soak/report.json`. Финальная сверка всех записей для этого запуска не выполнена, успешный долгий soak не заявляется.

Проверка ранее ожидала конкретный UID из API snapshot; при burst запись может покинуть UI-окно последних 100, даже когда GUI показывает более новые данные. В sampler добавлено принятие более нового sequence и диагностический snapshot при следующей ошибке. Это исправляет критерий проверки, но не устанавливает окончательную причину прежнего сбоя. Повтор длинного запуска отменён по указанию владельца; повторён только короткий сценарий.
